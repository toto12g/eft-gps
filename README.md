# EFT 測位クライアント

Escape from Tarkov のスクリーンショットの**ファイル名だけ**から現在地を読み取り、
マップ上に表示するブラウザ完結型のツール。

非公式のファンツールです。Battlestate Games とは無関係で、承認も受けていません。

## 安全域

| やること | やらないこと |
|---|---|
| ユーザーが選んだフォルダのファイル**名**を列挙する | 画像の中身を読む |
| `File.lastModified`（メタデータ）を読む | ゲームフォルダ・Logs の参照 |
| 別ウィンドウ／第 2 モニタでマップを描く | オーバーレイ・メモリ読み取り・インジェクション |
| すべてブラウザ内で完結させる | キー入力の自動送出（自動連写） |
| | 他プレイヤー・AI の位置の表示 |
| | 座標の外部送信 |

ゲームプロセスにもゲームフォルダにも一切触れません。サーバもありません。

## 必要なもの

- Python 3.10 以降（データ生成とテスト実行のみ。アプリの動作には不要）
- Chrome または Edge（File System Access API を使うため Chromium 系デスクトップ限定）
- Node.js は**不要**。ビルド工程がなく、素の ES モジュールをそのまま配信する。

## 使い方

`start.cmd` をダブルクリックすると、サーバを立てて Chrome で開くところまでやる。
手で起動する場合は次のとおり。

```
py -m http.server 8731 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8731/` を開く。`?map=customs&sample=<ファイル名>` で
初期状態を指定できる。

**公開してしまえばこの起動作業は要らない。** GitHub Pages などに置けば URL を
開くだけで動き、さらに PWA としてインストールすればデスクトップのアイコンから
ブラウザの UI 無しで開ける（下の「公開する」を参照）。

テスト:

```
py tools/run_tests.py       # サーバ起動 → headless Chrome で実行 → 結果表示
```

同梱データの再生成（tarkov.dev の更新を取り込むとき）:

```
py tools/build_data.py --refresh
```

校正の目視検証（脱出口が図の出口・扉に乗っているかを画像で確認する）:

```
py tools/shoot_calib.py            # 全マップ → tools/.shots/*.png
py tools/shoot_calib.py customs    # 指定したマップだけ
```

## 描画

Leaflet の CRS を「SVG のユーザ座標そのもの」にしている。

```
latLng         = [py, px]              lat = 画像 y, lng = 画像 x
transformation = 恒等 (1, 0, 1, 0)     y は下向きのまま
overlay        = svgOverlay(svg, [[0,0],[H,W]])   常に軸並行
```

こうするとマップ固有の知識がすべて 1 本のアフィンに集約され、CRS は全マップ共通になる。
tarkov.dev のように CRS 側で回転を組み立てると、フルアフィンが `L.Transformation` で
表現できず、`ImageOverlay` が軸並行でしか描けない問題にもぶつかる。

マーカーの向きは、進行ベクトルを画像空間へ写してから画面角を取る（`headingToScreenDeg`）。
アフィンが回転・反転・せん断のどれを含んでいても正しくなる。

## ファイル名の仕様

```
2026-09-03[07-31]_253.03, 4.36, 392.09_-0.02791, 0.97159, -0.18087, -0.15004_16.71 (0).png
^ 日時(分精度)   ^ position x,y,z    ^ quaternion x,y,z,w                  ^ゲーム内時刻 ^連番
```

- **position** は Unity 左手系のワールド座標（m）。`y` が高さ。2D 表示に使うのは `(x, z)`。
- **quaternion** は `(x, y, z, w)` の順。単位長で、実測上つねに `Ry(yaw)·Rx(pitch)` の形
  （roll が構造的に 0）。つまりカメラ（視線）の回転であって体の向きではない。
- **ゲーム内時刻** は 10 進時。`16.71` = 16:42。ワールド時計
  `(3h + epochMs × 7) mod 24h` と誤差 ±0.005h で一致することを実測で確認済み。
  ハイドアウトでは一致しない（ハイドアウトはワールド時計を使わない）。
- **連番** はファイル名衝突時の回避用。ファイル名に秒が無いため必要になる。

## 参照実装との違い

**yaw の式を修正している。** TarkovMonitor と tarkovgps.com は
`atan2(2(w·y + x·z), 1 − 2(y² + z²))` を使っているが、これは「Y 軸まわりの回転量」で
あって前方の方位ではない。見上げ角がつくと系統的にずれる（yaw=45° のとき pitch=30° で
4.1°、pitch=60° で 18.4°）。実測サンプルでも、見下ろし 55° の 1 枚で 15.6° の差が出た。
本実装は前方ベクトル `q·(0,0,1)` の方位角として求めるので、どの姿勢でも正しい。

**マップごとにフルアフィン（6 パラメータ）を持つ。** tarkov.dev の変換モデルは
「回転 + 軸並行スケール + 平行移動」でせん断を表現できず、そのため
`coordinateRotation` が 90/270 のときだけ +180 する場当たり補正が入っている。
フルアフィンにすればその特殊ケースが消える（下の「マップ校正」）。

**座標系を共有するシーンを統合している。** `factory` と `night-factory`、
`the-lab` と `the-lab-dark`、`ground-zero` 系 3 つは同じ座標空間なので、
統合しないと互いに距離 0 になり「2 位 / 1 位」の比による判定が機能しない。

## マップ校正

ワールド座標 (x, z) から SVG のユーザ座標へは、マップごとに **6 パラメータのフルアフィン**
1 本で変換する。

```
px = a·x + b·z + c
py = d·x + e·z + f
```

初期値は tarkov-dev の配置（`transform` + `coordinateRotation` + `bounds`／`svgBounds`、
Leaflet の `svgOverlay` が北西・南東の 2 点だけを投影して軸並行矩形に貼る挙動、
SVG の `preserveAspectRatio="xMidYMid meet"`）をそのまま再現して解析的に求めている。
`tools/build_data.py` の `analytic_affine()`。

10 マップすべてを `test/calib.html` で描画して目視検証済み。回転の 3 種類
（90° = factory、180° = 大半、195.209° = reserve）をすべて含む。

| map | POI が viewBox 内 | letterbox | 外れ値除去 | 目視検証 |
|---|---|---|---|---|
| customs | 99.6% | 0.24% | 4 | ✓ |
| factory | 96.5% | 0.04% | 82 | ✓ |
| ground-zero | 99.4% | 0.09% | 8 | ✓ |
| interchange | 99.7% | 0.11% | 0 | ✓ |
| lighthouse | 99.5% | 0.02% | 3 | ✓ |
| reserve | 99.7% | 0.11% | 4 | ✓ |
| shoreline | 98.7% | 0.01% | 0 | ✓ |
| streets-of-tarkov | 99.7% | 0.06% | 0 | ✓ |
| terminal | 100.0% | 0.06% | 0 | ✓ |
| woods | 99.0% | 0.04% | 0 | ✓ |
| icebreaker / the-lab / the-labyrinth | — | — | — | SVG なし。手動校正が必要 |

`Labs.svg` は SVG リポジトリに存在するが、tarkov-dev の `bounds` と縦横比が 10% 合わない
ため自動では採用していない。校正ツールで対応点を打てば使える。
the-labyrinth と icebreaker は SVG 素材そのものが存在しない。

### 校正ツール（calibrate.html）

ワールド座標が確定している点（脱出口）を地図画像の上でクリックして対応づけ、
最小二乗でアフィンを解く。残差 RMS がその場で出るので、精度を数値で確かめられる。

1. マップと地図画像（`maps/` の SVG）を選ぶ
2. 左の一覧から参照点を選び、地図上のその場所をクリック（ドラッグで移動、ホイールで拡大）
3. 2 点で相似変換、3 点以上でフルアフィン。POI 点群が図に重なるかで妥当性を見る
4. 「JSON をコピー」→ `data/calib-overrides.json` に貼る → `py tools/build_data.py`

既に校正済みのマップでは「初期値から出発」で現在の校正から対応点を生成できる。
微調整や、別の地図画像への載せ替えに使う。

自動生成された tarkov-dev の SVG は内容が viewBox の外まで描かれていることがあり
（Customs の content bbox は viewBox の 1.5 倍）、描画範囲からの自動位置合わせは
信用できない。だから対応点は人が打つ。

### POI の外れ値除去

tarkov.dev のデータには実際のマップ外に飛んでいる点が混ざっている（factory の `lootLoose`
に x=274.9 の点があるが、マップ幅は約 160 m しかない）。残すと別マップのサンプルが
そこに近いと判定されて最寄りマップを誤るため、`bounds` を各辺 10% 広げた矩形で足切りする。
factory で 82 点、全体で 65 点が落ちる。

## フォルダ監視

`src/watch/` が File System Access API でスクリーンショットフォルダを見る。
FSA には変更通知が無いので 1 秒ごとにポーリングし、`dirHandle.keys()`（名前だけを返す
いちばん安い呼び出し）の結果を前回と比べて差分を新着とする。

「初めて見た時刻を持って古いものを捨てる」方式にはしていない。まだフォルダに残っている
ファイルを期限切れで忘れると、次のポーリングで新着として再発火してしまうため。
差分方式なら集合はフォルダ内のファイル数で自然に頭打ちになり、削除も自動で反映される。

- 監視開始時点で既にあるファイルは既読にして、履歴を再生しない。過去ぶんは
  「直近 20 枚を読み込む」ボタンで明示的に。
- ディレクトリハンドルは IndexedDB に保存する。リロードすると権限は `prompt` に戻るので、
  起動時に `queryPermission()` を見て、必要なら「権限を許可」ボタンを 1 つ出す
  （`requestPermission()` はユーザー操作が必要）。フォルダ選択はやり直させない。
- `getFile()` は `lastModified` を取るためだけに呼ぶ。`File` は遅延ハンドルなので、
  `arrayBuffer()` / `text()` / `createImageBitmap()` を呼ばないかぎり画像のバイトは
  1 バイトも読まれない。`src/watch/index.js` にはそれらの呼び出しが存在しない。
- スクリーンショットの自動削除は実装しない。ユーザーのファイルは触らない。

`lastModified` が取れると、ゲーム内時計との整合（信号 S2）が使えるようになる。
ただし夜 Factory や Lab は時刻が固定され一致しないので、**肯定にだけ**使い、
不一致を理由にサンプルを捨てない。

## マップ判定

マップは手動選択。ただし選択ミスを黙って通さないよう、座標で検証する。

間違ったマップを選んでも**マップ外に飛ぶとは限らない**。実測で、Streets の座標
`(203.07, 402.38)` は 13 マップ中 7 マップの bbox 内に収まる。そのため bbox ではなく
POI 点群への最近傍距離を使う。

### 1 枚では決めない

Customs のレイド 16 枚を実測したところ、**単発の最近傍では 2 枚で別マップが 1 位**に
なった（woods 5.40 m、factory 3.14 m）。ロード類の POI から離れた開けた場所では
最寄り距離が 20〜28 m まで伸び、2位/1位 も 1.3 倍程度まで縮むため。

`MapTracker` が直近 12 枚の平均距離を持ち、そちらで判断する。実測 16 枚では
**3 枚目以降つねに customs が 1 位**になり、窓を広げるほど分離が上がる。

| 判定方法 | customs 以外を 1 位にした回数 |
|---|---|
| 単発（N=1） | 2 / 16 |
| 累積 N=2 以上 | 0 / 16 |

時計整合（S2）が使えない条件——夜 Factory や Lab のように時刻が固定されるマップ、
あるいは `lastModified` の無い手入力——で差がはっきり出る:

| | accept | 確信度 低 | レイド外として破棄 |
|---|---|---|---|
| tracker なし | 4 | 8 | **4** |
| tracker あり | 16 | 0 | 0 |

tracker が無いと、**実際にレイド中の 4 枚が「レイド外」として黙って捨てられる**。

### サンプル別の実測値

| サンプル | 1 位 | 2 位 | 比 | 判定 |
|---|---|---|---|---|
| Streets レイド 1 | streets 1.50 m | interchange 44.93 m | 30.0 | 単発でも確定 |
| Streets レイド 2 | streets 0.65 m | interchange 19.16 m | 29.7 | 単発でも確定 |
| Customs 16 枚 | customs 2.0〜27.9 m | — | 1.3〜44 | 累積で確定 |
| ハイドアウト | icebreaker 4.72 m | ground-zero 6.53 m | 1.39 | レイド外 |

ハイドアウトは「1 位が遠い」のではなく「全マップから等しく近い」（座標が原点付近）。
時計も 3.79 h ずれるので、累積が無くても除外できる。

閾値は `src/verify/index.js` の `DEFAULT_THRESHOLDS` にまとめてある。

**マップの自動追従は既定 ON。** 累積判定が 3 枚以上たまり、2位/1位 が 1.5 倍以上に
なったときだけ、選択中のマップを直す。1 枚の判定では絶対に切り替えない。

## タスクの目標地点

左サイドバーの「タスクの目標地点」でタスクを選ぶと、そのマップ上の目標地点が地図に出る。
**先にマップを選ぶこと。** タスク一覧はそのマップに目標があるものだけに絞られる。

- **268 タスク / 591 ゾーン / 419 候補地点**を tarkov.dev から取り込んでいる
- タスク名も目標の説明も**日本語**（例:「BTR のスペアホイール に MS2000 マーカー を取り付ける」）
- 目標ごとに現在地からの**距離・方位・相対方向**が出る。行をクリックするとその地点へ寄る
- 別マップにある目標は「別マップ」と表示して灰色にする（距離を出すと嘘になるため）
- 検索欄でタスク名・トレーダー・目標の説明から絞り込める
- `?task=<id>` で特定のタスクを開いた状態の URL を作れる

データはマップごとに `data/tasks/<map>.json` へ分けてあり、そのマップを開いたときだけ読む。
全 11 ファイルで 234 KB あるので、まとめて読むと起動が重くなる。

同じ目標が何十箇所にもなることがある（BTR の停車地点など）。そこに毎回説明文を描くと
地図が文字で埋まって読めなくなるので、**地点が 2 箇所以下のときだけ文字を出し、
多いときは番号だけ**にしている。説明はホバーと左の一覧で読める。

## ピン（タスクの目的地）

「地図をクリックして置く」を押してから地図上をクリックすると、その場所に印を置ける。
タスクの目標地点、集合場所、あとで戻りたい場所などに使う。

API に無い場所や自分用のメモには、手動のピンを使う。

- 「ピンを置く」を押している**間はオン**のままで、地図をクリックするたびに刺さる
  （もう一度押すか Esc で終了）。名前は一覧でクリックして書き換える
- ピンは**マップごと**に localStorage へ保存される
- 座標はワールド座標で持つので、地図画像や校正を差し替えても位置がずれない
- 1 つを「目的地」に指定すると、現在地から**距離・方位・相対方向**（正面／右 27°／真後ろ）が
  常時表示され、地図上にも破線が引かれる
- 現在地が更新されるたびに距離と方位が計算し直される

`src/app/pins.js` は DOM に依存しない純関数群なので、テストから直接叩ける。

## ゲーム内時計の実測

Customs のレイド 16 枚すべてで、ファイル名の値とワールド時計の式が **±0.4 分以内**に
一致した。21 分のレイドでゲーム内 142 分が経過（6.77 倍。理論値 7 倍に対し、
ファイル名の分精度による誤差の範囲）。

ハイドアウトの 1 枚だけが 3.79 h ずれる。ハイドアウトはワールド時計を使っていない。

## ジンバルロック

真下（または真上）を向いて撮ると、`pitch = ±90°` になり**方位が定義できない**。
実測 16 枚のうち 1 枚がこれに当たり、前方ベクトルの水平成分が `3.8e-6` まで潰れる。
`headingStrength()` が 0.09 を下回ったら矢印を描かず、丸だけを出す。嘘の向きを
描かないため。この 1 枚だけ `roll` の分解も 180° になる（残り 15 枚は `|roll| < 1°`）。


## 公開する（無料）

サーバーサイドのコードが無い完全な静的サイトなので、静的ホスティングに置くだけで
誰でも URL から使えます。配信サイズは約 2.0 MB。

**HTTPS が必須です。** File System Access API はセキュアコンテキストでしか動きません。
`http://` に置くとフォルダ監視だけが動かなくなります（手入力は動く）。

### GitHub Pages（推奨・完全無料）

ソース公開が CC BY-NC-SA の継承条項を自然に満たすので、いちばん相性が良い。

```
git init
git add .
git commit -m "EFT 測位クライアント"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

GitHub のリポジトリ → Settings → Pages → Source を **Deploy from a branch**、
Branch を **main / (root)** にして Save。数十秒後に次の URL で公開されます。

```
https://<ユーザー名>.github.io/<リポジトリ名>/
```

サブパス配下（`/<リポジトリ名>/`）での動作は検証済み。パスはすべて相対にしてあります。
`.nojekyll` を置いてあるので Jekyll による加工も入りません。

無料枠は「サイト 1 GB / 転送 100 GB per 月」なので、2 MB のこのサイトなら
月 5 万アクセスでも収まります。

### Cloudflare Pages（ソースを公開したくない場合）

Cloudflare Pages はフォルダの直接アップロードに対応しているので、Git リポジトリを
公開せずに配信できます。ただし CC BY-NC-SA の継承条項がある以上、改変版を配布する
なら結局ソースを提供する義務が残ります。

## 公開する（無料）

サーバーサイドのコードが無い完全な静的サイトなので、静的ホスティングに置くだけで
誰でも URL から使えます。配信サイズは約 2.0 MB。

**HTTPS が必須です。** File System Access API はセキュアコンテキストでしか動きません。
`http://` に置くとフォルダ監視だけが動かなくなります（手入力は動く）。

### GitHub Pages（推奨・完全無料）

ソース公開が CC BY-NC-SA の継承条項を自然に満たすので、いちばん相性が良い。

```
git init
git add .
git commit -m "EFT 測位クライアント"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

GitHub のリポジトリ → Settings → Pages → Source を **Deploy from a branch**、
Branch を **main / (root)** にして Save。数十秒後に次の URL で公開されます。

```
https://<ユーザー名>.github.io/<リポジトリ名>/
```

サブパス配下（`/<リポジトリ名>/`）での動作は検証済み。パスはすべて相対にしてあります。
`.nojekyll` を置いてあるので Jekyll による加工も入りません。

無料枠は「サイト 1 GB / 転送 100 GB per 月」なので、2 MB のこのサイトなら
月 5 万アクセスでも収まります。

### Cloudflare Pages（ソースを公開したくない場合）

Cloudflare Pages はフォルダの直接アップロードに対応しているので、Git リポジトリを
公開せずに配信できます。ただし CC BY-NC-SA の継承条項がある以上、改変版を配布する
なら結局ソースを提供する義務が残ります。
